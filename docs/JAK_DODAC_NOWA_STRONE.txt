==============================================================
JAK DODAĆ NOWĄ STRONĘ (np. "Zawodnicy") — SZABLON KROK PO KROKU
==============================================================

Ten plik to instrukcja "dla laika" — kolejność, w jakiej trzeba
tworzyć pliki, żeby dodać nową listę w administracji, wzorem
istniejącej strony "Mecze". Zamiast "Mecze" wstaw swój temat,
np. "Zawodnicy" — w tekście wszędzie, gdzie jest ZAWODNICY,
podstaw nazwę swojej strony.

Nie zmieniaj kolejności kroków. Każdy kolejny krok opiera się
na poprzednim.

OGÓLNY OBRAZEK — CO POWSTAJE I W JAKIEJ KOLEJNOŚCI

    1. MODEL           -> jak wygląda tabela w bazie (już gotowe,

        id: Mapped[int] = mapped_column(primary_key=True)

tabel, nie zmieniaj kolumn — model ma pasować do tego, co już
jest w bazie.

KROK 2. DOMENA — opisz "jedną pozycję listy" i "filtry"
--------------------------------------------------------------

Miejsce: src/handball/domain/players.py  (nowy plik)

Wzór: src/handball/domain/matches.py

Potrzebne są zwykle 3 klasy:

    @dataclass(frozen=True)
    class FiltryZawodnikow:
        szukaj_nazwiska: str | None = None
        strona: int = 1
        rozmiar_strony: int = 20

    @dataclass(frozen=True)
    class PozycjaListyZawodnikow:
        id_zawodnik: int
        imie: str | None
        nazwisko: str | None

    @dataclass(frozen=True)
    class StronaZawodnikow:
        pozycje: list[PozycjaListyZawodnikow]
        liczba_wszystkich: int
        strona: int
        rozmiar_strony: int

To są zwykłe "pudełka na dane" — żadnej logiki bazy danych,
żadnego Flaska. Dzięki temu dają się łatwo testować.

    class ZawodnikFilterForm(Form):
        nazwisko = StringField(validators=[validators.Optional()])
        strona = IntegerField(default=1, validators=[validators.Optional()])
        rozmiar_strony = IntegerField(default=20, validators=[validators.Optional()])

KROK 7. WIDOK — recepcjonista, który spina wszystko
--------------------------------------------------------------

Miejsce: src/handball/interface/admin/views/player_views.py

Wzór: src/handball/interface/admin/views/match_views.py

    class ZawodnikListView(MethodView):
        def __init__(self, fabryka_zaleznosci: ZaleznosciZadaniaFactory) -> None:
            self._fabryka_zaleznosci = fabryka_zaleznosci

        def get(self) -> str:
            formularz = ZawodnikFilterForm(request.args)
            if not formularz.validate():
                abort(400, description=str(formularz.errors))

            filtry = formularz.do_filtrow()
            serwis = self._fabryka_zaleznosci.utworz_serwis_zawodnikow()
            try:
                strona = serwis.pobierz_liste(filtry)
            except BladOdczytuDanych as wyjatek:
                obsluz_blad_domeny(wyjatek)

            return render_template(
                "admin/players/list.html",
                sekcja_aktywna="zawodnicy",
                strona=strona,
                filtry=filtry,
                formularz=formularz,
            )

NAZEWNICTWO — PRZYPOMNIENIE (patrz docs/CODING_STANDARDS.md)
--------------------------------------------------------------

- Nazwy plików, katalogów, modułów: PO ANGIELSKU
  (np. player_repository.py, players/list.html)
- Nazwy klas, metod, zmiennych domenowych: PO POLSKU, bez
  polskich znaków diakrytycznych, z angielską "rolą techniczną"
  na końcu nazwy klasy:
    ZawodnikService, ZawodnikRepository, ZawodnikListView,
    ZawodnikSQLAlchemyRepository, ZawodnikReadRepository
- Bez komentarzy w nowym kodzie i testach — wyjaśnienia idą
  do plików .md / docs.
- Nie twórz repozytorium/serwisu "na zapas" bez realnej potrzeby —
  jeśli nowa strona jest bardzo prosta (np. sam słownik bez
  filtrów), można pominąć osobny formularz i ograniczyć serwis
  do przekazania dalej, ale zachowaj podział na warstwy
  (kontrakt / repozytorium / widok) — to on daje testowalność.
